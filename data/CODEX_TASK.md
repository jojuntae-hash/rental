# CODEX_TASK.md

# 렌탈 견적 사이트 데이터 연동 작업

현재 이 저장소는 렌탈 견적 웹사이트 프로젝트다.

기존 사이트의 화면 디자인과 사용자 흐름은 최대한 유지하면서, 현재 하드코딩되어 있거나 임시로 관리되고 있는 상품/가격 데이터를 내가 제공한 통합 렌탈 데이터로 교체해라.

작업에 사용해야 할 파일:

- `쿠쿠_통합양식.xlsx`
- `코웨이_통합양식.xlsx`
- `SK매직_통합양식.xlsx`
- `렌탈_가격표_통합_DB_에이전트_설계서.md`

`렌탈_가격표_통합_DB_에이전트_설계서.md`를 먼저 읽고 데이터 구조와 변환 원칙을 이해한 뒤 작업을 시작해라.

---

## 1. 가장 먼저 할 일

현재 프로젝트 전체 구조를 먼저 분석해라.

특히 다음을 확인해라.

- 사용 중인 프레임워크
- 상품 데이터가 현재 어디에 저장되어 있는지
- 견적 계산 로직이 어디에 있는지
- 제품군/상품/모델/약정기간 선택 UI가 어떤 데이터 구조를 기대하는지
- 기존 하드코딩 데이터와 컴포넌트 간 의존성
- 배포 환경이 Vercel에서 정상 동작하는 구조인지

분석 후 별도의 확인을 기다리지 말고 바로 구현을 진행해라.

현재 UI를 전면 재작성하지 말고, 기존 디자인과 사용 흐름을 최대한 유지하면서 데이터 계층을 정리하는 방향으로 작업해라.

---

## 2. 사이트의 사용자 선택 흐름

사이트 견적 흐름은 다음 순서다.

```text
제품군 선택
  ↓
상품명 선택
  ↓
모델명 선택
  ↓
의무/약정기간 선택
  ↓
필요한 경우 서비스방식/점검주기/프로모션 선택
  ↓
최종 견적 표시
```

최종 견적에서는 최소한 다음 데이터를 표시할 수 있어야 한다.

- 회사명
- 제품군
- 상품명
- 모델명
- 의무사용기간
- 약정기간
- 서비스방식
- 점검주기
- 월 렌탈료
- 총수수료
- 프로모션

기본수수료와 추가수수료는 고객 화면에서 표시할 필요가 없다.

`총수수료`만 사용한다.

## 3. 데이터 구조

Excel에는 두 개의 시트가 있다.

### PRODUCT

상품 자체의 정보다.

주요 컬럼:

```text
product_id
회사명
제품군
원본제품군
상품명
display_name
모델명
세부모델명
상품명확인상태
상품명출처
기준월
비고
```

### RENTAL_OPTION

상품별 가격 및 렌탈 조건이다.

주요 컬럼:

```text
option_id
product_id
선택기간
약정기간
의무사용기간
소유권이전
서비스방식
관리방식
점검주기
구분
월렌탈료
총수수료
프로모션명
프로모션기간
프로모션내용
원본옵션명
기준월
비고
```

PRODUCT와 RENTAL_OPTION은 `product_id`로 연결한다.

한 PRODUCT에 여러 RENTAL_OPTION이 존재할 수 있다.

방문/셀프, 의무기간, 점검주기, 프로모션이 다르다고 PRODUCT를 별도 상품으로 복제하지 마라.

---

## 4. 중요한 데이터 원칙

엑셀의 금액은 숫자다.

예:

```text
51900
432086
```

이를 코드에서 `"51,900원"` 같은 문자열 데이터로 저장하지 마라.

화면 표시 단계에서만 다음처럼 포맷하라.

```text
51,900원
432,086원
```

기간 또한 가능한 경우 숫자를 기준으로 처리하고 화면에서 `60개월` 형태로 표시해라.

## 5. 권장 구현 방식

현재 프로젝트 구조를 확인한 뒤 가장 적절한 방법을 선택하되, 가능하면 원본 Excel을 프론트엔드에서 직접 읽게 하지 마라.

다음 구조를 우선 검토해라.

```text
/data/rental/
    쿠쿠_통합양식.xlsx
    코웨이_통합양식.xlsx
    SK매직_통합양식.xlsx

/scripts/
    build-rental-data.*

/generated 또는 /src/data/generated/
    products.json
    rental-options.json
```

빌드용 스크립트에서 3개 Excel을 읽어 하나의 공통 JSON 데이터로 생성한다.

```text
Excel 3개
   ↓
build-rental-data
   ↓
products.json
rental-options.json
   ↓
사이트
```

현재 프로젝트가 다른 구조를 사용하는 경우 프로젝트에 맞게 위치와 구현 언어는 변경해도 된다.

단, 역할 분리는 유지해라.

## 6. 통합 데이터

세 회사의 PRODUCT를 하나의 배열로 합쳐라.

예:

```ts
products = [
  ...cuckooProducts,
  ...cowayProducts,
  ...skmagicProducts
]
```

RENTAL_OPTION도 동일하게 하나의 배열로 합쳐라.

```ts
rentalOptions = [
  ...cuckooOptions,
  ...cowayOptions,
  ...skmagicOptions
]
```

회사별 데이터 구조를 프론트에서 각각 따로 처리하지 마라.

UI에서는 모든 회사를 동일한 데이터 인터페이스로 조회할 수 있어야 한다.

---

## 7. 조회 로직

제품군 목록:

```text
PRODUCT에서 고유한 제품군 값 추출
```

제품군 선택 후 상품 목록:

```text
선택 제품군에 해당하는 PRODUCT 필터
```

상품 선택 후 모델:

```text
해당 상품명에 해당하는 PRODUCT 필터
```

모델 선택 후 기간:

```text
해당 product_id의 RENTAL_OPTION에서 선택기간 또는 의무/약정기간의 고유값 추출
```

기간 선택 후 조건:

```text
해당 product_id + 선택기간에 맞는 RENTAL_OPTION 필터
```

같은 기간에도 다음 조건이 여러 개 있을 수 있다.

- 방문
- 셀프
- 점검주기
- 일반
- 패키지
- 프로모션

따라서 하나의 가격만 임의로 선택하지 말고 사용자가 구분할 수 있도록 처리해라.

## 8. 제품군

Excel의 PRODUCT 시트에 이미 사이트용으로 정규화된 `제품군`이 들어 있다.

따라서 원본 엑셀의 제품군을 다시 추론하지 말고 PRODUCT의 `제품군` 컬럼을 우선 사용해라.

예:

```text
정수기
얼음정수기
비데
공기청정기
매트리스
프레임
안마의자
안마베드
전기레인지
식기세척기
음식물처리기
```

## 11. 월별 업데이트 자동화

이 부분이 매우 중요하다.

앞으로 매달 가격표가 바뀔 예정이다.

다음 달에는 내가 새로운:

```text
쿠쿠_통합양식.xlsx
코웨이_통합양식.xlsx
SK매직_통합양식.xlsx
```

를 넣을 것이다.

그때 사이트 코드를 다시 수정하지 않고 파일만 교체한 뒤 하나의 명령으로 데이터를 갱신할 수 있어야 한다.

예:

```bash
npm run build:rental-data
```

또는 프로젝트에 적합한 명령을 만들어라.

가능하다면 일반 `npm run build` 전에 데이터 생성 스크립트가 자동 실행되도록 구성해라.

예:

```json
{
  "scripts": {
    "build:rental-data": "...",
    "prebuild": "npm run build:rental-data",
    "build": "..."
  }
}
```

프로젝트 환경에 맞춰 구현해라.

## 12. TypeScript 사용 시

TypeScript 프로젝트라면 PRODUCT와 RENTAL_OPTION 타입을 명확하게 정의해라.

예:

```ts
type RentalProduct = {
  productId: string
  company: string
  category: string
  productName: string
  displayName: string
  model: string
  detailModel?: string
}

type RentalOption = {
  optionId: string
  productId: string
  selectionPeriod?: number
  contractPeriod?: number
  mandatoryPeriod?: number
  ownershipPeriod?: number
  serviceType?: string
  managementType?: string
  inspectionCycle?: string
  type?: string
  monthlyPrice: number
  totalCommission: number
  promotionName?: string
  promotionPeriod?: number
  promotionDescription?: string
}
```

현재 프로젝트 코딩 스타일에 맞춰 이름은 조정해도 된다.

## 13. 기존 사이트 보존

기존 사이트가 이미 정상 작동하는 기능은 불필요하게 제거하거나 전면 재작성하지 마라.

특히 다음은 유지한다.

- 현재 레이아웃
- 현재 디자인
- 모바일 반응형
- 기존 견적 UI 흐름
- 기존 배포 설정
- 기존 URL

데이터 계층과 견적 선택 로직을 중심으로 수정한다.

필요한 리팩터링은 가능하지만 변경 범위를 최소화해라.

## 14. 데이터 검증

변환 과정에서 반드시 검사해라.

- 중복 product_id
- 중복 option_id
- RENTAL_OPTION의 product_id가 PRODUCT에 존재하지 않는 경우
- 모델명이 빈 상품
- 월렌탈료가 숫자가 아닌 행
- 총수수료가 숫자가 아닌 행
- 음수 가격
- 동일 옵션 완전 중복
- 상품은 있는데 옵션이 하나도 없는 경우

문제가 발견되면 빌드 로그에 알기 쉽게 표시해라.

심각한 데이터 오류는 빌드를 실패시키는 것도 가능하다.

## 17. 설계서 우선 원칙

`렌탈_가격표_통합_DB_에이전트_설계서.md`는 이 프로젝트 데이터 구조의 최신 기준 문서다.

이 파일과 현재 코드가 충돌하면:

1. 실제 원본 데이터 확인
2. 설계서의 의도 확인
3. 필요한 코드 수정
4. 설계 변경이 필요한 경우 설계서도 함께 수정

순서로 처리해라.

설계 변경이 발생하면 설계서와 코드가 서로 다른 상태로 남지 않도록 한다.
