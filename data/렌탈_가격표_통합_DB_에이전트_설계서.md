# 렌탈 가격표 통합 DB 구축 에이전트 설계서

> 버전: 1.0  
> 기준월: 2026-09  
> 목적: 쿠쿠, 코웨이, SK매직 등 서로 다른 형식의 렌탈 가격표 Excel을 분석해 웹 견적 시스템에서 공통으로 사용할 수 있는 표준 데이터 구조로 변환한다.

---

## 1. 프로젝트 목적

여러 렌탈 회사의 가격표 Excel은 사람이 보기에는 편하지만 회사별로 양식과 용어가 달라 프로그램에서 직접 사용하기 어렵다.

이 에이전트의 목표는 매월 새 가격표를 입력받아 다음 과정을 자동 수행하는 것이다.

1. 원본 Excel 구조 분석
2. 실제 상품/가격 데이터 영역 탐색
3. 병합셀/빈셀/정책 설명 영역 제거
4. 제품군 표준화
5. 상품명/모델명 정리
6. 렌탈 조건 분리
7. 프로모션 정규화
8. 월렌탈료/수수료 정규화
9. 공통 구조 Excel 생성
10. 향후 JSON/DB 변환이 가능한 형태로 저장

최종 웹 견적 흐름은 다음을 기준으로 한다.

```text
제품군 선택
  ↓
상품명 선택
  ↓
모델명 선택
  ↓
의무/약정기간 선택
  ↓
렌탈 조건 선택
  ↓
월렌탈료 + 총수수료 + 프로모션 표시
```

---

# 2. 입력 파일

기본 입력 파일 예시:

```text
쿠쿠 9월.xlsx
코웨이 9월.xlsx
SK매직 9월.xlsx
```

다음 달에는 파일명이 바뀔 수 있다.

예:

```text
쿠쿠 10월.xlsx
코웨이 10월.xlsx
SK매직 10월.xlsx
```

따라서 파일명을 완전히 고정해서 처리하지 말고 회사명을 기준으로 판별한다.

---

# 3. 출력 파일

회사별로 동일한 구조의 Excel을 생성한다.

```text
쿠쿠_통합양식.xlsx
코웨이_통합양식.xlsx
SK매직_통합양식.xlsx
```

각 파일에는 반드시 아래 두 시트를 생성한다.

```text
PRODUCT
RENTAL_OPTION
```

세 회사 파일은 컬럼 순서와 컬럼명이 완전히 동일해야 한다.

---

# 4. 핵심 설계 원칙

## 4.1 상품 정보와 가격 조건을 분리한다

같은 모델이 약정기간, 의무사용기간, 방문/셀프, 점검주기, 할인 여부 등에 따라 여러 가격을 가질 수 있다.

따라서 하나의 행에 상품과 모든 가격정보를 반복 저장하지 않는다.

구조:

```text
PRODUCT
  1
  │
  └── N
RENTAL_OPTION
```

즉:

- PRODUCT = 상품 자체
- RENTAL_OPTION = 렌탈 조건/가격/프로모션

---

# 5. PRODUCT 시트 표준 스키마

컬럼 순서는 아래와 같이 고정한다.

| 순서 | 컬럼명 | 설명 |
|---|---|---|
| 1 | product_id | 상품 고유 ID |
| 2 | 회사명 | 쿠쿠 / 코웨이 / SK매직 |
| 3 | 제품군 | 사이트용 표준 제품군 |
| 4 | 원본제품군 | 원본 Excel의 제품군 |
| 5 | 상품명 | 고객에게 보여줄 상품명 |
| 6 | display_name | 회사명 + 상품명 |
| 7 | 모델명 | 대표 모델번호 |
| 8 | 세부모델명 | 세부 모델/색상/파생 모델 |
| 9 | 상품명확인상태 | 원본확인 / 웹확인 / 자동생성 |
| 10 | 상품명출처 | 웹 확인 시 출처 URL |
| 11 | 기준월 | YYYY-MM |
| 12 | 비고 | 기타 메모 |

---

# 6. RENTAL_OPTION 시트 표준 스키마

컬럼 순서는 아래와 같이 고정한다.

| 순서 | 컬럼명 | 설명 |
|---|---|---|
| 1 | option_id | 옵션 고유 ID |
| 2 | product_id | PRODUCT 연결키 |
| 3 | 선택기간 | 사이트에서 기간 선택 시 사용할 대표 기간 |
| 4 | 약정기간 | 약정기간(개월) |
| 5 | 의무사용기간 | 의무사용기간(개월) |
| 6 | 소유권이전 | 소유권 이전 기간(개월) |
| 7 | 서비스방식 | 방문 / 셀프 / 무방문 / 서비스프리 등 |
| 8 | 관리방식 | 방문주기/관리형태/서비스 형태 |
| 9 | 점검주기 | 2개월 / 4개월 / 6개월 / 12개월 등 |
| 10 | 구분 | 일반 / 패키지 / 할인형 등 |
| 11 | 월렌탈료 | 숫자형 |
| 12 | 총수수료 | 숫자형 |
| 13 | 프로모션명 | 반값할인 / 타사보상 / 렌탈료할인 등 |
| 14 | 프로모션기간 | 개월 단위 숫자 |
| 15 | 프로모션내용 | 상세 설명 |
| 16 | 원본옵션명 | 원본 상세 옵션 문자열 |
| 17 | 기준월 | YYYY-MM |
| 18 | 비고 | 기타 메모 |

# 7. 숫자 저장 규칙

## 7.1 금액

금액은 반드시 숫자형으로 저장한다.

잘못된 저장:

```text
"51,900원"
"432,086원"
```

올바른 저장:

```text
51900
432086
```

Excel에서는 표시 형식만 다음처럼 적용한다.

```text
#,##0
```

표시 결과:

```text
51,900
432,086
```

이렇게 해야 추후:

- 가격 비교
- 합산
- 정렬
- JSON 변환
- DB 저장
- 견적 계산

이 가능하다.

---

# 8. 기간 저장 규칙

기간도 숫자형 저장을 원칙으로 한다.

예:

```text
36
60
72
84
```

Excel 표시 형식:

```text
0"개월"
```

표시 결과:

```text
36개월
60개월
```

단, 점검주기의 경우 `서비스프리`, `없음`, `1회서비스` 같은 값이 존재할 수 있으므로 텍스트 유지가 필요할 수 있다.

# 10. 상품명 처리 우선순위

상품명은 추측해서 확정하지 않는다.

우선순위:

## 1순위: 원본 Excel 상품명

원본에 상품명이 있다면 그대로 사용한다.

예:

```text
코웨이
상품명 = 루네어
```

```text
SK매직
상품명 = 원코크 플러스 얼음물 정수기
```

---

## 2순위: 제조사 공식 웹 확인

원본에 상품명이 없으면 모델번호로 제조사 공식 사이트를 검색한다.

확인 가능한 경우:

```text
상품명확인상태 = 웹확인
상품명출처 = 공식 URL
```

---

## 3순위: 원본 제품군 기반 자동생성

공식 상품명 확인이 어려운 경우 함부로 상품명을 만들지 않는다.

예:

```text
상품명 = 얼음 데스크형
상품명확인상태 = 원본제품군 기반 자동생성
```

이 값은 추후 사람이 검수할 수 있도록 상태를 반드시 남긴다.

---

# 11. product_id 생성 규칙

기본 형식:

```text
회사코드-모델명
```

예:

```text
CUCKOO-CP-AQS100EWH
COWAY-MC-R02S
SKMAGIC-WPUIAC425S
```

ID에는 가능한 한:

- 공백 제거
- 특수문자 정리
- 영문 대문자 사용

을 적용한다.

한 모델번호가 서로 다른 완전히 별개 상품으로 사용되는 예외가 있으면 상품명 해시나 순번을 붙여 충돌을 방지한다.

---

# 12. option_id 생성 규칙

옵션 ID는 단순 순번보다 내용 기반 안정 ID를 권장한다.

기본 구성요소:

```text
product_id
의무기간
약정기간
소유권
서비스방식
점검주기
구분
렌탈료
총수수료
프로모션
원본옵션명
```

이 값들을 조합해 SHA1 등의 해시 일부를 사용한다.

예:

```text
CUCKOO-CP-AQS100EWH-36509056B
```

이 방식은 옵션 정렬 순서가 바뀌어도 ID 안정성이 높다.

# 13. 회사별 파싱 규칙

---

# 13.1 쿠쿠

## 원본 구조 특징

주요 컬럼:

```text
제품군
모델명
모델명(세부)
구분
의무
소유권
점검주기
렌탈료
총 수수료(vat포함)
비고
```

제품군/모델명이 병합셀 형태로 반복 생략될 수 있으므로 아래 행에 값이 없으면 직전 값을 상속한다.

---

## 세부모델 파싱 예

원본:

```text
CP-AQS100EWH(S)(E/36M/4C/할인/6M반값)
```

변환:

```text
모델명 = CP-AQS100EWH
세부모델명 = CP-AQS100EWH(S)
의무사용기간 = 36
점검주기 = 4개월
프로모션명 = 반값할인
프로모션기간 = 6
```

---

## 다중 모델 셀

원본 모델명 셀에 여러 색상 모델이 함께 들어가는 경우가 있다.

예:

```text
CP-AHS100HEW
CP-AHS100HEG
CP-AHS100HEBR
CP-AHS100HEB
CP-AHS100HPK
```

세부모델명 컬럼을 확인해서 실제 행과 연결되는 모델을 식별한다.

세부모델이 wildcard 또는 복수 색상 공통 옵션이면 여러 PRODUCT와 동일 옵션을 연결할 수 있다.

---

## 매트리스 관리주기

다음 값은 PRODUCT를 분리하는 조건이 아니라 RENTAL_OPTION의 관리방식이다.

```text
매트리스 / 4개월 관리
매트리스 / 6개월 관리
매트리스 / 12개월 관리
매트리스 / 4개월 관리 + 교체
```

PRODUCT:

```text
제품군 = 매트리스
```

RENTAL_OPTION:

```text
관리방식 = 4개월 관리
점검주기 = 4개월
```

# 13.2 코웨이

## 원본 구조 특징

주요 컬럼:

```text
제품군
상품명
모델명
약정기간(의무사용기간)
반값할인 적용기간
점검주기
약정할인가
기본수수료
추가수수료
프로모션 관련 컬럼
총 수수료(vat포함)
타사보상(vat포함)
반값할인(vat포함)
```

---

## 수수료 규칙

중요:

단순히 다음 계산으로 총수수료를 만들지 않는다.

```text
기본수수료 + 추가수수료
```

반드시 원본 Excel의:

```text
총 수수료(vat포함)
```

값을 기준값으로 사용한다.

이유:

- VAT
- 회사별 계산 규칙
- 프로모션 수수료 조정

때문에 단순 합산값과 다를 수 있다.

---

## 반값할인 옵션

반값할인 수수료가 기본 총수수료와 다른 경우에는 별도 RENTAL_OPTION 행을 생성한다.

예:

```text
기본 옵션
총수수료 = 550,110

반값 옵션
총수수료 = 477,488
프로모션명 = 반값할인
```

---

## 점검주기/서비스 방식

예:

```text
12M(12개월점검주기)
```

변환:

```text
서비스방식 = 방문관리
점검주기 = 12개월
관리방식 = 12M(12개월점검주기)
```

예:

```text
서비스프리
```

변환:

```text
서비스방식 = 서비스프리
점검주기 = 빈값
```

---

# 13.3 SK매직

## 원본 구조 특징

주요 컬럼:

```text
프로모션
모델명
모델명(세부)
상세 옵션
의무
소유권
점검주기
렌탈료
총 수수료(vat포함)
```

SK매직은 모델/상품 정보와 서비스방식이 여러 셀에 섞여 있으므로 문자열 파싱이 중요하다.

---

## 예

원본:

```text
WPU-IAC425 방문(5년의무) 6개월반값할인
```

변환:

```text
모델명 = WPU-IAC425
서비스방식 = 방문
의무사용기간 = 60
프로모션명 = 반값할인
프로모션기간 = 6
```

---

## 서비스방식

문자열에서 다음을 추출한다.

```text
방문
셀프
무방문
서비스프리
```

우선순위:

```text
무방문 > 셀프 > 방문
```

---

## 비렌탈 행 제외

SK매직 가격표에는 렌탈이 아닌 다음 데이터가 포함될 수 있다.

```text
일시불
일시불 + 멤버쉽
필터 단품
에어센서 단품
```

# 18. 검수 규칙

파일 생성 후 반드시 아래 검사를 수행한다.

## PRODUCT 검수

- product_id 중복 없음
- 모델명 빈값 없음
- 회사명 빈값 없음
- 제품군 빈값 없음
- 모델명에 설명문/프로모션 문구가 섞이지 않았는지 확인
- `●`, `★`, `→` 등의 메모 문자가 모델명에 남지 않았는지 확인

## RENTAL_OPTION 검수

- option_id 중복 없음
- product_id가 PRODUCT에 존재하는지 확인
- 월렌탈료 숫자형 확인
- 총수수료 숫자형 확인
- 기간이 음수/비정상 값인지 확인
- Excel 오류값 확인

검색 대상:

```text
#REF!
#DIV/0!
#VALUE!
#NAME?
#N/A
```

# 28. 에이전트용 기본 프롬프트

아래 프롬프트를 에이전트의 기본 작업지침으로 사용할 수 있다.

```text
너는 렌탈 가격표 통합 DB 구축 에이전트다.

입력으로 쿠쿠, 코웨이, SK매직 등 렌탈 회사의 월별 Excel 가격표를 받는다.

각 회사의 원본 Excel 구조는 서로 다르지만,

1. 회사별 원본 구조를 먼저 분석한다.
2. 정책 설명 영역과 실제 가격 데이터 영역을 구분한다.

4. 제품군은 사이트용 표준 제품군으로 정규화한다.
5. 상품명은 원본 → 공식 웹 확인 → 자동생성 순으로 처리한다.
6. 상품과 렌탈 조건을 분리한다.
7. 월렌탈료와 총수수료는 숫자형으로 저장한다.
8. Excel 표시 시 금액은 콤마를 적용한다.
9. 프로모션은 옵션 단위로 관리한다.
10. 동일 모델의 방문/셀프/기간/프로모션 차이는 PRODUCT를 복제하지 않고 RENTAL_OPTION으로 분리한다.

12. 코웨이는 원본 VAT 포함 총수수료를 우선한다.
13. SK매직의 일시불/멤버십 등 비렌탈 행은 렌탈 DB에서 제외한다.
14. 변환 완료 후 ID 중복, 숫자형 금액, 모델명 이상값, Excel 오류를 검수한다.
15. 중간 승인을 기다리지 말고 정의된 범위 안에서는 끝까지 작업한다.
16. 긴 작업 중에는 실제로 수행한 단계 기준으로 상태를 짧게 표시한다.
17. 최종 결과는 회사별 동일 컬럼 구조의 Excel로 저장한다.
18. 향후 JSON/API/DB 변환이 쉬운 형태를 유지한다.
```

# 31. 설계서 실시간 동기화 원칙

이 프로젝트에서 작업 규칙, DB 구조, 회사별 파싱 규칙, 제품군 분류, 컬럼 정의, 검수 방식, 출력 방식, 자동화 방식이 변경되면 **해당 작업을 완료하는 같은 턴에서 이 설계서도 즉시 수정한다.**

- 프로모션 처리 방식 변경
- product_id / option_id 생성 방식 변경
- 원본 Excel 구조 변화 대응

- 웹사이트 연동 구조 변경
- JSON / DB 스키마 변경
- 검수 규칙 변경
- 자동화 폴더/파일 구조 변경

## 작업 방식

작업 변경 발생 시:

```text
실제 작업 수정
   ↓

   ↓

   ↓

```

사용자에게 별도 승인을 다시 요청하지 않고, 이미 합의된 프로젝트 범위 안의 변경은 작업 결과와 설계서를 함께 갱신한다.

원본 통합양식은 브라우저에서 직접 읽지 않는다. 빌드 단계에서 공통 JSON으로 변환하고 검증한다.

```text
        ↓
/api/data/excel
        ↓
렌탈 견적 대시보드
```

월별 갱신 명령:

```bash
npm run build:rental-data
```

`npm run build` 실행 시 `prebuild`에서 같은 변환과 검증을 자동 실행한다. 심각한 데이터 오류가 있으면 빌드를 실패시키며, 확인이 필요한 비치명 예외는 경고로 출력한다.
